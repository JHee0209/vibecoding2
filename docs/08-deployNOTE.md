## 2. 저장소 — localStorage 키 → 테이블

**`washed_typequeue` · `washed_machines` 줄은 F1 홈 화면을 만들며 실제로 옮겼다** — `src/lib/queue.ts` 가 `machines` · `queue` 표를 직접 읽고 쓰고, 스냅샷을 만들지 않는다. 대기 인원 · 예상 대기는 그때그때 세는 파생값이다(06 「대기 인원은 저장하지 않는다」 그대로). 아래 표의 나머지 줄(관리자 · 신고 · 공지 등)은 아직 프로토타입 그대로다.

| 키 | 쓰는 화면 | 옮길 곳 |
|---|---|---|
| `washed_typequeue` | 홈(쓴다) · 관리자(읽는다) | `queue` (사용자 · 기기종류 · 상태 · 배정 시각 · 배정 마감 · 수거 마감 · 06 「줄서기」). **지금 이 키에 들어 있는 것은 줄서기 항목 자체가 아니라 홈이 계산해 남긴 대기열 스냅샷**이다 — 종류별로 `count`(대기 인원 · 빈 기기가 있으면 0 · 05 P2) · `mine`(내가 그 줄에 있는지) · `waitLeftMs`(첫 대기자의 남은 시간, 대기자가 없으면 가장 먼저 끝나는 기기의 남은 시간) · `total`(그 종류의 기기 대수) · `available`(사용가능 대수). 홈은 **내가 줄을 섰는지와 무관하게 늘** 이 값을 다시 쓴다. 서버로 옮기면 이 스냅샷은 없애고 관리자 화면이 `queue` · `machine` 을 직접 조회해 세면 된다(06 「대기 인원은 저장하지 않는다」) |
| `washed_machines` · `washed_admin_faults` | 홈 · 관리자 | `machine` (이름 · 종류 · 상태 · 고장 여부) |
| `washed_maintenance` | 홈 · 관리자 | `laundry_room.maintenance` |
| `washed_warnings` | 홈 · 기록 · 관리자 | `warning_summary` (사용자별 누적 · 제한 종료 시각 · 06 「이용 제한」) |

| `washed_notices` | 관리자 · 알림 | `notice` |
| `washed_unread` | 알림 · 홈 · 기록 · 설정 | `notification` 테이블의 읽음 여부로 계산 |
| `washed_admin_id` | 관리자로그인 | 그대로 두어도 된다 (아이디 저장 편의 기능) |

## 3. 대기열 · 배정 — 동시성

**서버로 옮겼다** — `src/lib/queue.ts` 의 `joinQueue` · `leaveQueue` · `confirmQr` · `finishUsage` · `reconcile` 가 배정 · QR · 종료 · 만료를 전부 서버에서 판정한다. 화면(`src/app/home/home-view.tsx`)은 버튼을 누르고 결과만 받는다. "가장 먼저 끝나는 기기에 배정" (P2) · 줄 개수 제한(P1) · 배정 상태에서는 줄 빠지기 불가(P3) · 제한 중 차단(P7)도 화면이 아니라 서버가 막는다. `queue_machine_once_idx` UNIQUE 제약으로 같은 기기에 두 명이 배정되는 것은 막았다.

**여전히 강한 트랜잭션(행 잠금)은 쓰지 않는다** — Neon 서버리스 드라이버로 여러 문장을 한 트랜잭션으로 묶지 않고 순서대로 실행한다. 기숙사 한 곳 · 동시 사용자가 많지 않은 규모를 전제로 한 의도적인 단순화이고, 위 UNIQUE 제약이 최소한의 안전판이다 — 배정이 정말 겹치면 뒤에 온 요청이 에러로 실패하고 다음 정리(`reconcile`) 때 다시 시도된다. 실제 배포 규모가 커지면 이 자리부터 트랜잭션으로 옮긴다.

**관리자의 실시간 대기열(F23)은 아직 손대지 않았다** — 관리자 콘솔 자체가 아직 없다(7번 「제작 순서」). `src/lib/queue.ts` 의 대기 인원 계산(P2)을 그대로 재사용하면 되므로, 만들 때 규칙을 두 번 적지 않는다.

## 4. 시간 · 만료 처리

**"서버 스케줄러" 대신 "읽을 때마다 정리"로 만들었다** — `src/lib/queue.ts` 의 `reconcile()` 이 홈 화면을 열거나(`GET /home`) 줄서기 관련 버튼을 누를 때마다 배정 10분 초과 · 사용 종료 · 수거 3분 초과를 그 자리에서 처리한다. cron 이나 별도 워커가 없어도 되지만, **아무도 홈을 열지 않고 아무 버튼도 누르지 않으면 만료 처리도 미뤄진다** — 다음에 누군가(다른 사람이어도 된다) 홈을 열 때 한꺼번에 정리된다. 매월 1일 경고 초기화(P7)는 이 방식으로도 못 잡는다(달이 바뀌어도 아무도 안 건드리면 그대로다) — 이건 진짜 배치가 필요하다.

시간 표시는 서버 시각(`assign_deadline_at` · `ends_at` · `pickup_deadline_at`) 기준이고, 화면은 그 값과 로컬 1초 타이머로 카운트다운만 그린다 — 실제 만료 판정은 항상 다음 `reconcile()` 호출이 내린다. 화면 전체 갱신은 `setInterval` 로 5초마다 `router.refresh()` 를 부르는 짧은 폴링으로 바꿨다 — SSE · WebSocket 은 아직이다.

**기산점을 서버가 정한다.** 다음 사람의 배정 10분은 앞사람이 "다했어요" 를 눌렀거나 3분이 지나 자동 종료되어 **기기가 사용가능이 된 서버 시각**부터 센다(02 「시간 흐름」 · 05 상태값). 앞사람의 3분은 다음 사람의 10분에 들어가지 않는다.

**경고는 한 번만 쌓는다.** "다했어요" 미클릭과 세탁물 미수거가 겹쳐도 통합 1회다(05 P6) — 자동 판정과 관리자 수동 부여가 같은 건에 두 번 붙지 않도록 서버에서 막는다.

**앱을 안 켠 사람도 경고를 받아야 한다.** 지금은 화면을 열지 않으면 배정 만료 경고가 기록되지 않는다.

## 11. 다국어 (04 F37 · 05 P25)

**`i18n.js` 를 앱으로 그대로 옮겼다** — `public/i18n.js`(원본에서 아이콘 경로 `./icons` → `/icons` 만 바꾼 복사본)를 `src/app/layout.tsx` 가 `afterInteractive` 로 불러온다. 런타임 번역기와 `<lang-picker>` 가 둘 다 이 파일에 있어서, 언어 버튼은 로그인 화면 오른쪽 위와 설정의 「언어」 묶음 두 곳에 원본 그대로 들어간다(`src/types/lang-picker.d.ts` 가 타입만 얹는다). **원본이 바뀌면 다시 복사한다 — `public/i18n.js` 를 직접 고치지 않는다.**

- 번역은 `i18n.js`(화면 문구) · `i18n-docs.js`(약관 · 개인정보 동의서)의 **한국어 원문을 키로 쓰는 사전**이다. 화면을 만들 때 문구를 새로 쓰면 사전에도 같이 넣어야 하고, 넣지 않으면 **오류 없이 한국어 그대로 보인다** — 배포 전 네 언어로 한 번씩 돌아보는 점검이 필요하다. React 로 옮긴 화면들이 쓰는 새 문구 중 사전에 없는 것이 아직 남아 있다
- `i18n-docs.js`(약관 본문 번역)는 아직 붙이지 않았다 — 회원가입의 약관 시트는 한국어 본문만 보여준다
- 지금은 `MutationObserver` 로 DOM 의 텍스트 노드를 훑어 바꾼다. 화면이 많아지면 비용이 커지므로, 서버 렌더링으로 옮길 때는 **키 기반 번역 파일**(`ko.json` · `en.json` · `zh.json` · `ja.json`)로 바꾸고 한국어 원문을 키에서 떼어낸다
- 선택한 언어는 `localStorage` 의 `washed_lang` 에 있고 계정에 붙지 않는다(2번 표). 기기를 바꾸면 다시 골라야 하는데, 이대로 둘지는 팀이 정한다
- **서버가 만드는 문장**(알림 제목 · 내용 · 신고 결과 문구)은 지금 화면에서 번역된다. 서버 발송으로 옮기면 **푸시 알림은 번역되지 않으므로**, 사용자 언어를 서버가 알고 그 언어로 만들어 보내야 한다(5번과 함께 본다)
- 관리자가 직접 쓰는 공지는 번역하지 않는다(05 P25) — 다국어 공지가 필요하면 관리자 화면에 언어별 입력칸이 생겨야 한다
- 중국어 · 일본어 글꼴(Noto Sans SC · JP)을 구글 폰트에서 받아 쓴다. 기숙사 망에서 외부 폰트를 못 받으면 글자가 깨지므로 **자체 호스팅**을 준비해 둔다

| 발송 키 한 쌍 | 공개 키는 화면(`NEXT_PUBLIC_VAPID_PUBLIC_KEY`), 비밀 키는 **서버에만**(`VAPID_PRIVATE_KEY` · `.env.local`) | 이 앱이 보낸 알림임을 증명한다. 비밀 키가 클라이언트로 내려가면 안 된다 |
| 기기별 구독 저장 | 06 「푸시 구독」 · `src/app/api/push/subscribe/route.ts` | 누구의 어느 기기로 보낼지. 보내다 실패하면 지운다 |

**허용 안내(F40)와 구독 저장까지 만들었다** — `src/app/home/notification-prompt.tsx`(홈 첫 진입에서 한 번만 보이는 배너 · `localStorage` 의 `washed_push_asked` 로 다시 묻지 않는다) → `Notification.requestPermission()` → `navigator.serviceWorker.register('/sw.js')` → `pushManager.subscribe()` → `POST /api/push/subscribe` 로 이어진다. API 는 로그인(세션)을 확인하고 `endpoint` 가 겹치면(같은 기기) `user_id` 만 갈아 끼운다. `DELETE /api/push/subscribe` 로 구독을 지울 수 있다(서버 API 만 — 화면에 끄는 버튼은 아직 없다). curl 로 로그인 → 가짜 구독 등록 → DB 확인 → 삭제까지 재현해 확인했다.

**`.env.local` 의 VAPID 키 두 줄이 가짜였다.** `NEXT_PUBLIC_VAPID_PUBLIC_KEY`(19자) · `VAPID_PRIVATE_KEY`(20자)가 실제 키 길이(87자 · 43자)에 한참 못 미쳐 `web-push` 가 바로 던졌다 — `npx web-push generate-vapid-keys` 로 다시 만들어 넣었다. `.env.local.example` 에도 이 셋(`NEXT_PUBLIC_VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY` · `VAPID_SUBJECT`)이 아예 없어서 새로 적었다. **이 키를 다시 바꾸면 그 전에 등록된 구독은 전부 못 쓰게 된다** — 지금은 등록된 진짜 구독이 없어서(테스트로 넣은 가짜 구독은 지웠다) 문제가 없었다.

**테스트 발송 스크립트를 만들었다** — `scripts/dev-push.mjs`(`npm run dev:push`). `test@g.eulji.ac.kr` 의 구독을 찾아 알림 하나를 실제로 보내고, 성공하면 `last_success_at` 을 찍고 실패하면 그 구독을 지운다(P26). 구독이 없으면(아직 브라우저에서 "허용하기" 를 누른 적이 없으면) 안내만 하고 끝난다 — **이 스크립트는 구독을 만들지 않는다**, 홈 화면 배너를 실제로 눌러야 한다.

**F5 · F9 · 경고 자리에 실제로 붙였다** — `src/lib/push.ts`(앱 런타임용 발송 함수) · `src/lib/notify.ts`(알림함 INSERT + 푸시 발송을 한 번에 묶는 자리)를 새로 만들었고, `src/lib/queue.ts` 가 배정(F5) · 종료(F9) · 경고 세 군데에서 `notify()` 를 부른다. `dev-push.mjs` 는 그대로 두었다(코드는 같지만 plain node 스크립트라 별도 파일이다 — dev-user.mjs 가 hash.ts 를 옮겨 쓴 것과 같은 이유). **아직 안 한 것**: F31 신고 결과 알림(신고 처리 화면 자체가 없다) · 아이폰 홈 화면 추가 안내(F41) · 설정 화면의 "알림이 꺼져 있어요" 줄과 알림 끄기 버튼 · 서버가 사용자 언어로 문구를 만들어 보내기(11번, 지금은 전부 한국어).

**보내는 자리는 이미 정해져 있었고, 이제 실제로 돈다.** 알림함에 줄을 남기는 곳마다 폰 알림도 함께 나간다 — 배정(F5) · 종료(F9) · 경고. 신고 결과(F31)는 아직이다. 알림함 기록은 허용 여부와 상관없이 **늘 남긴다**(P26) — `notify()` 가 `notifications` INSERT 를 먼저 하고 푸시 발송은 그 뒤에 별도로 시도한다.

**아이폰 제약.** 사파리로 열어둔 상태에서는 폰 알림이 오지 않는다. 홈 화면에 추가해야만 받으므로 홈 첫 진입에서 안내한다(F41). 이 조건을 만족하려면 앱이 홈 화면에 추가될 수 있는 형태여야 한다.

**알림 문구는 번역 사전에 있다.** 배정 · 종료 알림 두 문장(「10분 안에 QR 코드를 찍어주세요…」 · 「3분 안에 세탁물을 수거해주세요」)이 `i18n.js` 에 네 언어로 들어 있다. 다만 그 번역은 **화면이 그릴 때만** 걸리므로, 서버가 보내는 푸시는 여전히 한국어로 나간다 — 사용자 언어를 서버가 알고 그 언어로 만들어 보내야 한다(11번).
